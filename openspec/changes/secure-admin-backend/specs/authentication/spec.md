# 规范：认证系统

## 新增需求

### 需求：AUTH-001 - 注册接口必须受保护

注册接口不能公开访问,必须通过环境变量或邀请码机制进行保护。

#### 场景：生产环境禁止公开注册

**前置条件**:
- 应用运行在生产环境
- 环境变量 `ALLOW_REGISTRATION` 未设置或为 false

**操作**:
- 用户访问 `/api/auth/register` 端点
- 提交有效的注册信息（邮箱、密码）

**预期结果**:
- 返回 403 状态码
- 返回错误消息："注册已关闭"
- 不创建新用户

#### 场景：开发环境允许注册

**前置条件**:
- 应用运行在开发环境（NODE_ENV=development）

**操作**:
- 用户访问 `/api/auth/register` 端点
- 提交有效的注册信息

**预期结果**:
- 成功创建用户
- 返回 201 状态码
- 返回用户信息（不含密码）

### 需求：AUTH-002 - 注册时不能默认创建管理员角色

新注册的用户默认角色必须为 USER,而非 ADMIN。

#### 场景：普通注册创建普通用户

**前置条件**:
- 注册功能已启用

**操作**:
- 用户通过注册接口创建账号
- 未提供角色参数

**预期结果**:
- 创建的用户角色为 USER
- 用户状态为 ACTIVE
- 不具有管理员权限

### 需求：AUTH-003 - 登录必须验证用户状态

登录时必须检查用户状态,BANNED 或 DELETED 状态的用户不能登录。

#### 场景：活跃用户可以登录

**前置条件**:
- 用户存在且状态为 ACTIVE

**操作**:
- 用户提交正确的邮箱和密码

**预期结果**:
- 登录成功
- 创建会话
- 返回用户信息

#### 场景：被封禁用户不能登录

**前置条件**:
- 用户存在但状态为 BANNED

**操作**:
- 用户提交正确的邮箱和密码

**预期结果**:
- 登录失败
- 返回错误消息："账号已被封禁"
- 不创建会话

#### 场景：已删除用户不能登录

**前置条件**:
- 用户存在但状态为 DELETED

**操作**:
- 用户提交正确的邮箱和密码

**预期结果**:
- 登录失败
- 返回错误消息："账号不存在"
- 不创建会话

### 需求：AUTH-004 - 会话必须包含用户角色信息

NextAuth 会话对象必须包含用户的角色信息,以便进行权限检查。

#### 场景：会话包含完整用户信息

**前置条件**:
- 用户已登录

**操作**:
- 获取当前会话信息

**预期结果**:
- 会话包含 user.id
- 会话包含 user.email
- 会话包含 user.name
- 会话包含 user.role

## 修改需求

### 需求：AUTH-005 - 更新 NextAuth 配置以支持角色

必须修改 NextAuth 配置,在 JWT 和 session 回调中添加角色信息。

#### 场景：JWT 包含角色信息

**前置条件**:
- 用户登录成功

**操作**:
- NextAuth 创建 JWT token

**预期结果**:
- JWT payload 包含 user.id
- JWT payload 包含 user.role

#### 场景：Session 包含角色信息

**前置条件**:
- 用户已有有效的 JWT

**操作**:
- 获取会话信息

**预期结果**:
- session.user.id 存在
- session.user.role 存在
- 角色值为 USER、ADMIN 或 MODERATOR 之一

# 提案：后台管理系统安全加固与功能完善

## 概述

本提案旨在解决 BlogT3 后台管理系统中存在的严重安全漏洞和功能缺口，确保系统在上线前达到最低安全标准，并具备稳定运营所需的核心功能。

## 问题陈述

当前后台管理系统存在以下关键问题：

### P0 级别（阻塞上线）

1. **任何人可写库/可上传的高危风险**
   - 后台写操作在客户端使用 anon key 直接操作数据库
   - 注册接口公开且默认创建 ADMIN 角色
   - 上传接口无鉴权且允许跨域
   - 任何访问者都可能创建管理员、写入内容、上传文件

2. **后台写入与当前登录用户未绑定**
   - 文章/相册创建时通过"取第一个用户"来兜底 authorId
   - 无法审计谁创建/修改了内容
   - 后续权限隔离困难

3. **数据模型/命名体系割裂**
   - Prisma 使用 PascalCase（Post/Category/Tag）
   - 旧 SQL 脚本使用 snake_case（posts/categories/tags）
   - 不同代码路径混用不同命名，导致功能随机失效

4. **前台读接口可能暴露草稿/未发布内容**
   - getPostBySlug 不限定 status
   - 公开路由可能通过 slug 访问草稿文章

### P1 级别（核心功能缺口）

1. **文章管理能力不足**
   - 缺少搜索、筛选、排序功能
   - 标签编辑 UI 缺失
   - 无草稿自动保存、预览功能
   - 缺少批量操作

2. **分类/标签管理能力不足**
   - 只能创建/删除，无法编辑
   - 删除时无保护机制
   - 缺少排序和统计功能

3. **相册/图片管理能力不足**
   - 图片排序未持久化
   - 缺少批量操作
   - 相册标签编辑 UI 缺失
   - 缺少删除功能

4. **评论/互动/反馈无后台管理**
   - 无评论审核台
   - 无反馈工单管理
   - 数据一致性策略不统一

## 目标

### 短期目标（M1：安全与一致性定稿）

- 统一数据库表命名体系
- 所有后台写操作服务端化并强制鉴权
- 公开读取只返回 PUBLISHED 内容
- 草稿预览走鉴权通道

### 中期目标（M2：后台可运营）

- 完善文章管理功能（搜索、筛选、标签、批量操作）
- 完善分类/标签管理（编辑、删除保护、排序）
- 完善相册管理（排序、批量操作、标签）

### 长期目标（M3：产品化）

- 评论审核和反馈工单管理
- 审计日志和权限细分
- 性能优化和监控

## 范围

### 包含

- 后台认证和授权机制改造
- 数据访问层统一和安全加固
- 文章/分类/标签/相册管理功能完善
- 评论和反馈管理功能

### 不包含

- 前台用户界面改进
- 性能优化和缓存策略（M3）
- 自动化测试（M3）
- 监控和告警（M3）

## 约束

- 必须保持与现有 Prisma schema 的兼容性
- 必须使用 NextAuth 进行认证
- 必须使用 Server Actions 或受保护的 API 路由进行写操作
- 不能破坏现有的前台功能

## 成功标准

1. 所有后台写操作都需要 ADMIN 角色验证
2. 注册接口受保护或仅在开发环境可用
3. 上传接口需要管理员身份验证
4. 公开 API 只返回 PUBLISHED 状态的内容
5. 所有内容创建都正确绑定当前登录用户
6. 后台管理界面提供完整的 CRUD 功能
7. 数据库命名体系统一且一致

## 风险

1. **数据迁移风险**：统一命名体系可能需要数据迁移
2. **向后兼容性**：现有客户端代码可能依赖旧的 API
3. **开发工作量**：涉及多个模块的重构
4. **测试覆盖**：缺少自动化测试可能导致回归问题

## 替代方案

### 方案 A：数据库层 RLS（Row Level Security）

**优点**：
- 在数据库层面强制安全策略
- 不依赖应用层自觉

**缺点**：
- Supabase RLS 配置复杂
- 与 Prisma 集成有限制
- 调试困难

### 方案 B：完全迁移到 tRPC

**优点**：
- 端到端类型安全
- 统一的 API 层

**缺点**：
- 需要重写大量代码
- 学习曲线陡峭
- 与 Next.js Server Actions 冲突

### 推荐方案：Server Actions + 权限中间件

**优点**：
- 与 Next.js 15 最佳实践一致
- 代码改动最小
- 易于理解和维护

**缺点**：
- 需要在每个 action 中添加权限检查
- 需要统一的权限工具函数

## 依赖

- NextAuth 5.0 会话管理
- Prisma ORM
- Supabase PostgreSQL
- 七牛云存储服务

## 时间线

本提案不提供具体时间估算，但建议按以下里程碑顺序实施：

1. M1：安全与一致性定稿（优先级最高）
2. M2：后台可运营（核心功能）
3. M3：产品化与质量提升（增强功能）

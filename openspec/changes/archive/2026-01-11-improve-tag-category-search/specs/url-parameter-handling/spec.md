# 规范：URL 参数处理

## 功能 ID
`url-parameter-handling`

## 目的
统一博客搜索功能中的 URL 参数格式，确保分类和标签链接使用 ID 作为参数值，实现正确的文章筛选。

---

## 修改需求

### 需求：分类链接使用 ID 参数
所有分类相关的链接必须使用分类 ID 作为 URL 参数，而不是 slug。

#### 场景：文章卡片分类徽章链接
- **当** 用户点击文章卡片上的分类徽章
- **那么** 应跳转到博客页面
- **并且** URL 应包含 `?category={categoryId}` 参数
- **并且** 博客页面应正确筛选该分类的文章

#### 场景：分类徽章组件接收 ID
- **给定** CategoryBadge 组件接收一个包含 id 字段的 category 对象
- **当** 渲染分类链接
- **那么** 应优先使用 category.id 作为参数值
- **并且** 如果 id 不存在，应回退使用 category.slug
- **并且** 链接格式应为 `/blog?category={id}`

---

## 新增需求

### 需求：标签链接使用 ID 参数和 tags 参数名
所有标签相关的链接必须使用标签 ID 作为 URL 参数值，并使用 `tags` 作为参数名（支持多选）。

#### 场景：侧边栏标签链接
- **当** 用户点击侧边栏的某个标签
- **那么** 应跳转到博客页面
- **并且** URL 应包含 `?tags={tagId}` 参数
- **并且** 博客页面应显示包含该标签的所有文章

#### 场景：文章元数据标签链接
- **当** 用户点击文章卡片或文章详情页的标签
- **那么** 应跳转到博客页面
- **并且** URL 应包含 `?tags={tagId}` 参数
- **并且** 博客页面应正确筛选包含该标签的文章

#### 场景：标签组件接收 ID
- **给定** PostMeta 组件接收一个包含 id 字段的 tag 对象
- **当** 渲染标签链接
- **那么** 应优先使用 tag.id 作为参数值
- **并且** 如果 id 不存在，应回退使用 tag.slug
- **并且** 链接格式应为 `/blog?tags={id}`

#### 场景：标签参数名称一致性
- **给定** 系统中存在多个标签链接来源（侧边栏、文章卡片、文章详情）
- **当** 渲染任何标签链接
- **那么** 所有链接都应使用 `tags` 作为参数名（复数形式）
- **并且** 不应使用 `tag`（单数形式）作为参数名
- **并且** 这确保了与 BlogSearch 组件的参数期望一致

---

## 修改需求（关联 search 规范）

### 需求：URL 查询参数同步（扩展）
扩展现有的 URL 查询参数同步需求，明确参数格式规范。

#### 场景：分类参数格式
- **当** 用户通过任何方式选择分类筛选
- **那么** URL 应更新为 `?category={categoryId}`
- **并且** categoryId 应为分类的 UUID
- **并且** 不应使用 slug 或 name

#### 场景：标签参数格式
- **当** 用户通过任何方式选择标签筛选
- **那么** URL 应更新为 `?tags={tagId}`
- **并且** tagId 应为标签的 UUID
- **并且** 多个标签应用逗号分隔：`?tags={tagId1},{tagId2}`
- **并且** 不应使用 slug 或 name

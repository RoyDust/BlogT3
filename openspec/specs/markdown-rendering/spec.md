## 需求
### 需求：统一的 Markdown 内容渲染

系统必须提供统一的 Markdown 渲染组件，用于在前台展示和编辑器预览中渲染 Markdown 格式的文章内容。

#### 场景：渲染基础 Markdown 语法
- **当** 组件接收包含基础 Markdown 语法的内容（标题、段落、列表、粗体、斜体、链接、图片等）
- **那么** 系统必须正确渲染这些元素为对应的 HTML 结构
- **并且** 渲染结果必须应用 Tailwind Typography 的 `prose` 样式类

#### 场景：渲染 GitHub Flavored Markdown 特性
- **当** 组件接收包含 GFM 特性的内容（表格、任务列表、删除线、自动链接等）
- **那么** 系统必须正确渲染这些 GFM 扩展语法
- **并且** 表格必须具有边框和交替行背景色
- **并且** 任务列表必须显示为可视化的复选框（不可交互）

#### 场景：代码块语法高亮
- **当** 组件接收包含代码块的内容
- **那么** 系统必须对代码块应用语法高亮
- **并且** 必须根据代码块指定的语言标识符应用相应的高亮规则
- **并且** 如果未指定语言，必须显示为纯文本代码块
- **并且** 行内代码必须使用等宽字体和背景色区分

#### 场景：明暗主题自适应
- **当** 用户切换系统主题（明亮模式或暗色模式）
- **那么** Markdown 渲染内容必须自动适配当前主题
- **并且** 代码高亮必须使用与主题匹配的配色方案
- **并且** 文本颜色、背景色、边框等必须符合当前主题的视觉风格

#### 场景：在文章详情页展示
- **当** 用户访问文章详情页
- **那么** 系统必须使用 Markdown 渲染组件展示文章内容
- **并且** 渲染结果必须替代原有的纯文本展示
- **并且** 必须保持响应式设计，在移动端正常显示

#### 场景：在编辑器中预览
- **当** 管理员在编辑器中输入 Markdown 内容
- **那么** 编辑器预览区域必须使用相同的 Markdown 渲染组件
- **并且** 预览效果必须与前台展示完全一致（所见即所得）
- **并且** 预览必须实时更新以反映编辑内容的变化

### 需求：安全的内容渲染

系统必须确保 Markdown 渲染过程的安全性，防止 XSS 攻击和恶意脚本注入。

#### 场景：过滤危险的 HTML 标签
- **当** Markdown 内容中包含原始 HTML 标签
- **那么** 系统必须默认不渲染这些 HTML 标签
- **并且** 必须将 HTML 标签作为纯文本显示
- **并且** 禁止启用允许渲染原始 HTML 的插件（如 `rehype-raw`）

#### 场景：安全的链接处理
- **当** Markdown 内容中包含外部链接
- **那么** 系统必须为外部链接添加 `rel="noopener noreferrer"` 属性
- **并且** 外部链接必须在新标签页中打开（`target="_blank"`）
- **并且** 必须防止 `javascript:` 协议的链接被渲染

### 需求：优雅的排版样式

系统必须为 Markdown 渲染内容提供美观简约的排版样式，提升阅读体验。

#### 场景：应用 Typography 样式
- **当** 渲染 Markdown 内容
- **那么** 系统必须应用 Tailwind Typography 的 `prose` 样式类
- **并且** 必须使用 `prose-lg` 提供大号舒适的字体尺寸
- **并且** 必须使用 `max-w-none` 避免内容宽度限制

#### 场景：代码块样式优化
- **当** 渲染代码块
- **那么** 代码块必须具有圆角边框和适当的内边距
- **并且** 代码必须使用等宽字体
- **并且** 代码块必须支持横向滚动以处理长行代码
- **并且** 代码高亮配色必须与整体设计风格协调
